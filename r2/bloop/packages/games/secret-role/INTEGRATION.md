## 2. `scripts/build-packs.mjs` — pack adapter

Append this block to the script. It maps the authored
`content/packs/double-jeu.json` items (shape: `{ id, mediaType, theme, majority,
impostor, closeness, spicyLevel }`) into the runtime `SecretRoleContent`
(`{ id, theme, majority, impostor }` — `mediaType`/`closeness`/`spicyLevel` are
offline-pipeline concerns the reducer never reads).

Two filters, both load-bearing:
- `spicyLevel 0` only (launch packs are all-ages, same rule as every game).
- **theme-leak lint**: drop any item whose majority/impostor string appears
  inside its own (PUBLIC) theme — that would both spoil the round in the room
  AND false-positive the redaction audit's substring check. The authored pack
  currently has exactly one such item (`cuisine-chef-patissier`: theme contains
  "Chef" = majority.en).

```js
// ---------------------------------------------------------------------------
// secret-role: double-jeu (odd-one-out) -> apps/server/src/content/secret-role-pack.ts
// ---------------------------------------------------------------------------
const dj = load('double-jeu');
// Authoring lint enforced at build time: the PUBLIC theme must never contain
// either HIDDEN word (gameplay spoiler + redaction-audit substring collision).
const themeLeaks = (i) =>
  [i.majority.fr, i.majority.en, i.impostor.fr, i.impostor.en]
    .some((w) => i.theme.fr.includes(w) || i.theme.en.includes(w));
const djItems = dj.items
  .filter((i) => (i.spicyLevel ?? 0) === 0 && !themeLeaks(i))
  .map((i) => ({ id: i.id, theme: i.theme, majority: i.majority, impostor: i.impostor }));

const djOut = join(root, 'apps', 'server', 'src', 'content', 'secret-role-pack.ts');
writeFileSync(djOut, `import type { ContentPack } from '@bloop/engine';
import type { SecretRoleContent } from '@bloop/game-secret-role';

/**
 * GENERATED by scripts/build-packs.mjs from content/packs/double-jeu.json —
 * do not edit by hand. theme is PUBLIC; majority / impostor are VALUE SECRETS
 * until finalReveal (they never enter a pre-reveal view). Items whose theme
 * contains either word are dropped at build time (theme-leak lint). Same R2
 * seam as tracer-pack.
 */
export const DOUBLE_JEU_PACK: ContentPack<SecretRoleContent> = {
  id: '${dj.gameId}-core',
  version: ${dj.version ?? 1},
  data: { items: ${JSON.stringify(djItems, null, 2)} },
};
`);
console.log(`secret-role-pack.ts regenerated — double-jeu: ${djItems.length} items (spicy 0, no theme leaks)`);
```

Emitted export: **`DOUBLE_JEU_PACK`** in
`apps/server/src/content/secret-role-pack.ts`. Run `node scripts/build-packs.mjs`
from the bloop root after pasting.

## 3. `apps/server/test-node/redaction-audit.test.ts` — AUDITS fixture

The file's shared `vote` helper already produces this game's vote action shape
(`{ kind: 'vote', target }`). Add one raw-deadline helper next to it (or inline
the literals as below) and the fixture entry:

```ts
  ['double-jeu', {
    players: ['p1', 'p2', 'p3', 'p4'],  // module minPlayers is 4
    seed: 'audit-seed',
    // Two deadlines skip secretReveal + discuss p0, then two secret accusation
    // ballots are buffered mid-vote m0 p0 — p3/p4 still expected, phase NOT
    // advanced. Both scripts produce identical hasVoted booleans and (at any
    // later deadline) a top TIE, so the resolution path is identical too.
    events: [
      { type: 'deadline', at: 1_000 },
      { type: 'deadline', at: 2_000 },
      vote('p1', 'p2', 3_000),
      vote('p2', 'p3', 4_000),
    ],
    eventsAlt: [
      { type: 'deadline', at: 1_000 },
      { type: 'deadline', at: 2_000 },
      vote('p1', 'p3', 3_000),
      vote('p2', 'p1', 4_000),
    ],
    actors: ['p1', 'p2'],
    // The current match's majority AND impostor words are VALUE secrets: at the
    // mid-vote fixture state NO view carries any word (myItem exists only in
    // secretReveal views), so no owner exemption is declared. The impostor
    // IDENTITY is also secret pre-finalReveal but is structural (a player id —
    // every id legitimately appears in views), so substring auditing cannot
    // apply: it is covered by the non-actor invariance check here plus the
    // package's own field-level tests (test/redaction.test.ts).
    secrets: (state) => {
      const s = state as {
        match: number;
        items: Array<{ majority: { fr: string; en: string }; impostor: { fr: string; en: string } }>;
      };
      const item = s.items[s.match];
      if (item === undefined) return [];
      return [
        { value: item.majority.fr },
        { value: item.majority.en },
        { value: item.impostor.fr },
        { value: item.impostor.en },
      ];
    },
  }],
```

Deadline-walk budget: from the fixture state the walk is exactly 19 steps to
`over` (4 beats finish match 0 — the buffered tie misses, verdict, discuss p1,
all-abstain vote 2 — then 1 beat into match 1 and 7 beats × 2 remaining
matches), under the audit's 25. Verified against the real authored pack in
`test/audit-fixture.test.ts` (same seed, same events, leakedSecrets included).

Note the fixture events INCLUDE the two deadline events — `fold` applies them
through `reduce`, and the module accepts them (state advances), so the
"rejected fixture event" guard stays quiet.

## Phase/timer reference (for reviewers)

| phaseKey | duration | early exit |
|---|---|---|
| `secretReveal:m{n}` | 12 s | all connected ack |
| `discuss:m{n}:p0` | 120 s | all connected ready |
| `vote:m{n}:p0` | 25 s | all connected voted |
| `verdict:m{n}:p0` | 8 s | — (display beat; only when vote 1 missed) |
| `discuss:m{n}:p1` | 90 s | all connected ready |
| `vote:m{n}:p1` | 25 s | all connected voted |
| `finalReveal:m{n}` | 12 s | — |
| `over` | untimed | terminal |

Caught = UNIQUE plurality on the impostor; tie / wrong target / all-abstain =
miss (ties favor the impostor, impostor doc §4.5 verbatim). THE impostor
disconnecting pre-finalReveal ends the match immediately (civilians +1
consolation, impostor 0); the next match's seeded impostor order skips
disconnected players.
