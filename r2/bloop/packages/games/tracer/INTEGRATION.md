# INTEGRATION — `pires-potes` (Pires Potes / Worst Mates) on the tracer/VOTE@1 module

`pires-potes` is a **pure config** on the existing `@bloop/game-tracer` machinery
(design §2.3, by-game spec `docs/designs/wave2-raw/by-game/pires-potes.json`):
vote a PLAYER, every player tied at the max tally gets +1, 7 rounds × (20 s vote
+ 7 s reveal). The module now ships a `createTracer(id, config?)` factory and
accepts bilingual `{fr,en}` prompts (`TracerContent.prompts: Array<string | LText>`,
passed through `view()` AS-IS — the client picks the locale). The legacy
`tracer` export is untouched.

Apply the snippets below verbatim. Owners of the shared files do the pasting —
nothing in this package edits them.

---

## 1. Server registry — `apps/server/src/room/registry.ts`

Replace the tracer import line and add the pack import:

```ts
import { createTracer, PIRES_POTES_CONFIG, tracer, tracerActionSchema } from '@bloop/game-tracer';
import { PIRES_POTES_PACK } from '../content/pires-potes-pack.js';
```

Add the entry to the `REGISTRY` map (after the `'tracer'` entry):

```ts
  ['pires-potes', {
    module: createTracer('pires-potes', PIRES_POTES_CONFIG),
    actionSchema: tracerActionSchema,
    content: PIRES_POTES_PACK,
  }],
```

`PIRES_POTES_CONFIG` is exported by this package:
`{ totalRounds: 7, voteMs: 20_000, revealMs: 7_000 }` (binding per design §2.3).

## 2. Pack generation — `scripts/build-packs.mjs` adapter

The authored master is `content/packs/pires-potes.json`; items are
`{ id, text: {fr,en}, spicy: 0|1, tags }`. The runtime data collapses to the
VOTE module's `{ prompts: LText[] }` — tracer consumes it unchanged. The core
pack ships **only `spicy === 0`** items (166 of 210 today); tier-1 cards are
reserved for the 18+ `pires-potes` spicy sibling config (later, per design).

NOTE: pires-potes items rate spiciness with the field `spicy` (per the by-game
contentItemShape), not `spicyLevel` like the option-vote packs — do not reuse
`safeItems()` as-is.

Append to `scripts/build-packs.mjs`:

```js
// pires-potes: designation cards -> the tracer/VOTE module's prompts array.
// Items use `spicy` (0|1|2) per the by-game spec; core pack = spicy 0 only.
const pp = load('pires-potes');
const ppPrompts = pp.items.filter((i) => (i.spicy ?? 0) <= 0).map((i) => i.text);

const ppOut = join(root, 'apps', 'server', 'src', 'content', 'pires-potes-pack.ts');
writeFileSync(ppOut, `import type { ContentPack } from '@bloop/engine';
import type { TracerContent } from '@bloop/game-tracer';

/**
 * GENERATED by scripts/build-packs.mjs from content/packs/pires-potes.json —
 * do not edit by hand. Bilingual {fr,en} designation cards; view() passes them
 * through AS-IS and the client picks the locale. Same R2 seam as tracer-pack.
 */
export const PIRES_POTES_PACK: ContentPack<TracerContent> = {
  id: '${pp.gameId}-core',
  version: ${pp.version ?? 1},
  data: { prompts: ${JSON.stringify(ppPrompts, null, 2)} },
};
`);
console.log(`pires-potes-pack.ts regenerated — ${ppPrompts.length} prompts (spicy 0 only)`);
```

Then run from the bloop root: `node scripts/build-packs.mjs`.

Emitted export: **`PIRES_POTES_PACK`** in
`apps/server/src/content/pires-potes-pack.ts` (new generated file — keeps the
`OptionVoteContent`-typed `option-vote-packs.ts` single-purpose).

## 5. Play routing — `apps/mobile/app/room/[code]/play.tsx`

**No routing change needed.** `pires-potes` is NOT in `OPTION_VOTE_GAME_IDS`,
so the existing fall-through in `Play()` already routes it to `TracerPlay`:

```tsx
  if (isOptionVoteGame(state.viewGameId)) return <OptionVotePlay code={code ?? ''} />;
  return <TracerPlay code={code ?? ''} />;   // tracer AND pires-potes land here
```

**Prompt rendering.** `asTracerView` (in `src/games/tracer-view.ts`) now accepts
`string | LText` prompts and **locale-resolves them to a plain string**
(via `promptText` + `deviceLang`) before `TracerPlay` ever sees them, so the
existing `{tv.prompt}` render lines in `play.tsx` work unchanged and compile.
If the team later switches `asTracerView` to raw pass-through, this is the
exact `TracerPlay` patch — both prompt renders go through `promptText`
(a plain-string prompt passes through unchanged, so the patch is safe to apply
today as defense in depth):

```tsx
import { asTracerView, deviceLang, promptText, secondsLeft } from '../../../src/games/tracer-view';
// vote phase card:
<AppText role="titleM" style={{ textAlign: 'center' }}>{promptText(tv.prompt, deviceLang())}</AppText>
// reveal phase subtitle:
<AppText role="body" color="textSecondary" style={{ textAlign: 'center' }}>{promptText(tv.prompt, deviceLang())}</AppText>
```
