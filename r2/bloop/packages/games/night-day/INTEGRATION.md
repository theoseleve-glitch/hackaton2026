# @bloop/game-night-day — integration (game id: `loup-garou`)

NIGHT_DAY (wave2 §2.17): moderator-less werewolf. v1 minimal role set — wolf,
villager, seer, witch. Night runs as sequential role-gated sub-phases under the
decoy protocol (identical screens, identical tap counts); day is dawn →
debate → secret lynch vote → reveal. One match = one module instance ending in
`gameOver` (the catalog's long-form anchor; interstitials only at the `over`
boundary). minPlayers 5, maxPlayers 16.

Workspace links already exist (`apps/server` and `apps/mobile` both depend on
`@bloop/game-night-day: workspace:*`) — no `package.json` edits needed.

All snippets below are copy-pasteable verbatim.

## 2. `scripts/build-packs.mjs` — pack adapter

Append this block to the script. It maps the authored
`content/packs/loup-garou.json` items into the runtime `NightDayContent`:
roleCards keep `{ id, type, role, name, text }`, narrations keep
`{ id, type, slot, text }`; `tags` and the top-level `meta` are authoring-side
only. Two filters, both load-bearing:

- **v1 role set**: roleCards outside `wolf|villager|seer|witch` (hunter, cupid,
  guardian, littleGirl, captain) are dropped until their mechanics land —
  shipping a card for a role nobody can hold would only confuse the reveal.
- **known slots**: narrations outside the eight v1 slots are dropped (forward
  compatibility with future authored slots).

```js
// ---------------------------------------------------------------------------
// night-day: loup-garou -> apps/server/src/content/night-day-pack.ts
// ---------------------------------------------------------------------------
const lg = load('loup-garou');
const LG_V1_ROLES = ['wolf', 'villager', 'seer', 'witch'];
const LG_SLOTS = [
  'night.intro', 'dawn.death', 'dawn.noDeath',
  'lynch.wolf', 'lynch.villager', 'lynch.none',
  'over.village', 'over.wolves',
];
const lgItems = lg.items.flatMap((i) => {
  if (i.type === 'roleCard') {
    return LG_V1_ROLES.includes(i.role)
      ? [{ id: i.id, type: 'roleCard', role: i.role, name: i.name, text: i.text }]
      : []; // v2 cards wait for their mechanics
  }
  return LG_SLOTS.includes(i.slot)
    ? [{ id: i.id, type: 'narration', slot: i.slot, text: i.text }]
    : [];
});

const lgOut = join(root, 'apps', 'server', 'src', 'content', 'night-day-pack.ts');
writeFileSync(lgOut, `import type { ContentPack } from '@bloop/engine';
import type { NightDayContent } from '@bloop/game-night-day';

/**
 * GENERATED by scripts/build-packs.mjs from content/packs/loup-garou.json —
 * do not edit by hand. Flavor-only pack (role cards + narration variants):
 * mechanics never read it, so themed reskins are pure config+pack drops.
 * v2 roleCards are dropped until their mechanics land. {victim}/{target}
 * tokens are substituted client-side with nicknames — the engine never sees
 * names. Same R2 seam as tracer-pack.
 */
export const LOUP_GAROU_PACK: ContentPack<NightDayContent> = {
  id: '${lg.gameId}-core',
  version: ${lg.version ?? 1},
  data: { items: ${JSON.stringify(lgItems, null, 2)} },
};
`);
console.log(`night-day-pack.ts regenerated — loup-garou: ${lgItems.length} items (v1 roles + narration)`);
```

Emitted export: **`LOUP_GAROU_PACK`** in
`apps/server/src/content/night-day-pack.ts`. Run `node scripts/build-packs.mjs`
from the bloop root after pasting.

## 3. `apps/server/test-node/redaction-audit.test.ts` — AUDITS fixture

This exact fixture is mirrored verbatim (and kept green) by the package's own
`packages/games/night-day/test/audit-fixture.test.ts`, so it cannot rot
silently. Seed `'audit-seed'` with roster `p1..p5` deterministically assigns:
**p1=wolf, p2=seer, p3=witch, p4/p5=villagers** (role assignment draws from
the rng before any pack data, so the real `LOUP_GAROU_PACK` yields the same
roles as the test pack).

```ts
  ['loup-garou', {
    players: ['p1', 'p2', 'p3', 'p4', 'p5'],  // module minPlayers is 5
    seed: 'audit-seed', // deterministic: p1=wolf, p2=seer, p3=witch, p4/p5=villagers
    // Three leaves shrink alive∧connected to {p1,p2} so the dawn win-check
    // room-collapses inside the audit's 25-step deadline walk. Then a seer
    // peek and a wolf vote are buffered mid night:r0:wolves — p2 has not
    // tapped sleep, so the phase is NOT advanced in either script.
    events: [
      { type: 'playerLeft', playerId: 'p3', at: 500 },
      { type: 'playerLeft', playerId: 'p4', at: 600 },
      { type: 'playerLeft', playerId: 'p5', at: 700 },
      { type: 'deadline', at: 1_000 },
      { type: 'action', playerId: 'p2', action: { kind: 'seerPeek', target: 'p4' }, at: 2_000 },
      { type: 'deadline', at: 3_000 },
      { type: 'action', playerId: 'p1', action: { kind: 'wolfVote', target: 'p3' }, at: 4_000 },
    ],
    eventsAlt: [
      { type: 'playerLeft', playerId: 'p3', at: 500 },
      { type: 'playerLeft', playerId: 'p4', at: 600 },
      { type: 'playerLeft', playerId: 'p5', at: 700 },
      { type: 'deadline', at: 1_000 },
      { type: 'action', playerId: 'p2', action: { kind: 'seerPeek', target: 'p5' }, at: 2_000 },
      { type: 'deadline', at: 3_000 },
      { type: 'action', playerId: 'p1', action: { kind: 'wolfVote', target: 'p4' }, at: 4_000 },
    ],
    actors: ['p1', 'p2'],
    // Role assignments are the VALUE secrets, audited as the PAIR string
    // `"<pid>":"<role>"` exactly as it would serialize inside a leaked roles
    // map. Bare role names cannot be substring-audited — the PUBLIC
    // composition census legitimately carries them as keys in every view.
    // Seer-peek targets, wolf-vote targets and lynch ballots are structural
    // (player ids appear legitimately everywhere), so they are covered by
    // the non-actor invariance check above plus the package's field-level
    // tests (test/redaction.test.ts).
    secrets: (state) => {
      const s = state as { players: string[]; roles: Record<string, string> };
      return s.players.map((p) => ({ value: `"${p}":"${s.roles[p]}"`, owner: p }));
    },
  }],
```

Deadline-walk budget: from the fixture state, 3 steps reach `over`
(`night:r0:wolves` → `night:r0:witch` → `dawn:r0` → roomCollapsed at the dawn
win-check), far under the audit's 25.

Note the fixture events INCLUDE the playerLeft and deadline events — `fold`
applies them through `reduce` and the module accepts every one (presence flips
and phase advances are state changes), so the "rejected fixture event" guard
stays quiet.

## Phase/timer reference (for reviewers)

| phaseKey | duration | early exit |
|---|---|---|
| `roleReveal` | 15 s | all alive∧connected acked |
| `night:r{n}:seer` | 25 s | all alive∧connected acted (decoy protocol) |
| `night:r{n}:wolves` | 30 s | all alive∧connected acted |
| `night:r{n}:witch` | 25 s | all alive∧connected acted |
| `dawn:r{n}` | 10 s | — (fixed display; win-check on deadline) |
| `debate:r{n}` | 90 s | all alive∧connected ready |
| `vote:r{n}` | 30 s | all alive voters voted |
| `lynch:r{n}` | 10 s | — (fixed display; win-check + `round_completed` on deadline) |
| `over` | untimed | terminal |

Rules of note: night sub-phases for a dead/disabled role are SKIPPED when
`revealRoleOnDeath=true` and run decoy-only when `false` (so the skip itself
cannot leak which role died). Wolf-vote ties resolve to the earliest
first-vote among tied (event order, no rng); lynch ties = no lynch.
Win-check order: zero wolves → village; wolves ≥ non-wolves → wolves;
alive∧connected < 3 → roomCollapsed (zero scores); round ≥ maxRounds(10) →
side with more alive. Scoring: villageWins → +2 living village / +1 dead
village / 0 wolves; wolvesWin → +3 living wolf / +1 dead wolf / +1 all
village. Disconnects never flip `alive`; a disconnected sole wolf produces
kill-less nights with roomCollapse + maxRounds as floors.
